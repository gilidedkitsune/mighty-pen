# Competitor analysis for outranking

Use this when a competitor's URL is given, or the goal is to outrank pages that already rank.

**Data:** live web search by default. If the Insights plugin is installed and wired, its `seo-geo` skill lists which SERP and competitor tools are connected; use those first. Never invent positions or metrics.

---

## 1. Collect the results and inventory each page

### 1a. Search

Search the exact target keyword on Google and on Bing, without changing it. Use Insights' SERP tools where wired; otherwise use web search.

- Take the top three organic results per engine. Skip ads, featured snippets, and "people also ask" boxes.
- Gather up to six URLs in total. If a URL shows up on both engines, count it once and note that it ranks on both.

Record the inventory before opening any page:

| # | Engine | URL | Title as shown | Position |
|---|---|---|---|---|

Before reading a single page, note what the results have in common. Mostly how-tos? Listicles? Product pages? Opinion pieces? That tells you the dominant search intent.

### 1b. Inventory each page

Open each URL and capture:

| Signal | What to record |
|---|---|
| Title tag | Exact text and length |
| Meta description | Exact text and length |
| H1 | Exact text |
| H2s and H3s | The full list, in order |
| Length | Approximate word count |
| Target keyword | The phrase the page is built around |
| Repeated terms | Words and phrases that recur through the body |
| Slug | The URL path |
| Internal links | Anchor text and destination, including links to product or pricing pages |
| External links | Sources and outbound links |
| Call to action | What it asks for, and where it sits |
| Dates | Published and last updated |
| Byline | A named author, or none |
| Structured data | Any schema markup |

Make one table per page, labeled with its URL and SERP position.

### 1c. A user-supplied competitor

If the user also gave a competitor URL, inventory it the same way and label it "user-provided" so it stays distinct from the search results.

---

## 2. Judge the quality

Score each area honestly. The aim is to find where the competition is beatable.

- **Depth and coverage:** does it answer the query fully, or skim? Which expected subtopics are missing or thin? Does it go past common knowledge?
- **Accuracy and freshness:** are the figures current? Look for stale stats, retired tools, and old advice. Are claims sourced, or simply asserted?
- **Structure and readability:** do the headings build an argument? Are sections balanced, or padded? Does the intro reach the point, or spend 200 words getting there? Is it scannable?
- **Intent match:** informational pages should teach; how-to pages should give steps; commercial pages should help the reader compare and decide. Note any mismatch with the keyword.
- **Calls to action:** is the call to action relevant, or bolted on? Does the post earn it?

---

## 3. Find the gaps

List the specific gaps. Each one is a place to win:

- **Content gaps:** subtopics or angles a reader would want and the page doesn't cover.
- **Depth gaps:** sections that exist but are too shallow.
- **Freshness gaps:** outdated material you can replace with current data or examples.
- **Perspective gaps:** the page says what but not why it matters, or who it matters to (developers, founders, enterprise teams).
- **Structure gaps:** the information is there but buried or hard to scan.
- **Intent gaps:** the page targets the keyword but doesn't answer the reader's real question.

---

## 4. Choose the angle

Don't write the same post at greater length. Pick one strategy:

| Strategy | Use it when |
|---|---|
| **Go deeper** | The competitor is shallow, and you can cover the topic more usefully and thoroughly |
| **Sharper angle** | The competitor is generic, and you can speak to one audience or use case directly |
| **Fresher take** | The competitor is out of date, and you have current data, examples, or context |
| **Better structure** | The competitor is hard to scan, and a cleaner structure alone is the win |
| **Product-led** | The competitor can't connect the topic to a product, and you can do it naturally |
| **Stronger point of view** | The competitor is neutral to a fault, and a clear stance makes the post more memorable |

Name the chosen strategy in the brief, under competitor context.

---

## 5. The competitor block in the brief

Include this block in any brief where a competitor URL is involved:

```
### Competitor analysis: [competitor URL]

**Their angle:** one sentence on what they're going for
**Length:** about [X] words
**What they do well:** honest strengths
**Gaps:**
- [gap]
- [gap]
- [gap]
**Our angle:** one or two sentences on what makes this version better
**Strategy:** [go deeper / sharper angle / fresher take / better structure / product-led / stronger point of view]
```

---

## Several competitor URLs

Run sections 1 to 3 on each one, then compare them:
- What does every page cover? That's table stakes, and the piece must include it.
- What does only one page cover? Worth considering.
- What does no page cover? That's the largest opportunity.

Build one angle that beats the whole field, not a post that beats one page.
